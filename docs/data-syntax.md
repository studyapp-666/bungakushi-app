# data/*.json 記法まとめ

`data/*.json`は、見出し・アイテム・boxの3種類のブロックを配列で並べたもの。
各ブロックの`text`(またはbox内アイテムの`text`)には、独自のインライン記法が使える。

## ブロックの種類

### heading（見出し）

```json
{ "type": "heading", "text": "歌物語" }
```

- セクション見出し。`<h2 class="section-heading">`として描画される。
- `text`にインライン記法は使えない（`appendKernedText`のみを通すため、括弧の字間調整以外は効かない）。

### item（通常アイテム）

```json
{ "type": "item", "id": "monogatari-001", "text": "歌物語は…" }
```

- `id`はページ内で一意な文字列。ファイル名から取った接頭辞＋連番にする（例: `monogatari-001`、`waka-004`）。
- `text`は文字列でも、文字列の配列でもよい。配列にすると改行区切りで書けて読みやすい（内部で`\n`結合してから処理される）。
- `text`中の`\n`（配列なら要素の切れ目）は`.line-break`という改行専用spanになる。

### box（枠）

```json
{
  "type": "box",
  "title": "歌物語|歌物語は以下の順で覚える",
  "items": [
    { "id": "monogatari-b01", "text": "①…" }
  ]
}
```

- `title`は省略可（`""`にすると見出しなしの枠になる）。
- `title`に`|`を1つ入れると、前半がメインタイトル（`--color-accent`色）、後半が注釈（`box-title-note`、やや小さめ・`--color-text`色）になり、間に`｜`区切りが入る。`|`がなければ全体がメインタイトルの見た目になる。
- `items`の各要素は`id`＋`text`（通常アイテムと同じ形）。
- box内アイテムは`text`中に`…`があると、`…`より前を折り返さないラベル、後ろを本文として横並びにし、本文が折り返した時にラベルの直後の位置に自動で揃う（固定インデントではなく可変幅ラベルに対応するための仕組み）。

### box作成時のルール

- boxを作るときは、`items`を空配列のままにせず、空の`id`だけ入れたプレースホルダーを作っておく（`{ "id": "<接頭辞>-b01", "text": "" }`など）。
- ただし中身の`text`は指示がない限り書かない（枠だけ用意する）。

## インライン記法（`text`内で使えるもの）

`js/main.js`の`parseTextToFragment`が処理する。ネスト可能なもの同士は組み合わせられる。

### `[[答え|ヒント]]` — 空欄（タップで解答表示）

```
[[{伊勢|いせ}物語|歌物語]]
```

- タップで答えが表示される`.blank`ピルになる。
- `ヒント`は省略可（省略時は「？」表示）。
- 答え・ヒントの中に`{base|reading}`（ルビ）を書ける。

### `{base|reading}` — ルビ（ふりがな）

```
{在原業平|ありわらのなりひら}
```

- 通常のテキスト中では素の`<ruby>/<rt>`になる。
- `[[ ]]`（空欄）の中に書いた場合だけ、独自のspanで見た目を作る（ブラウザ間で`<ruby>`の内部box modelが揺れるのを避けるため）。

### `{{語句|注釈}}` — 語句の下に注釈（参考書の朱色補足のイメージ）

```
{{和歌|五七五七七の歌}}
{{[[{伊勢|いせ}物語|歌物語]]|注釈テキスト}}
```

- `語句`の直下（行間）に`--color-accent`色の小さい注釈が付く。
- `語句`部分は空欄（`[[ ]]`）やルビ（`{ }`）を含んでもよい（再帰的に解釈される）。
- `語句`が空欄そのものの場合、注釈の左端はピルの空白マージン分を無視してピルの実際の左端に揃う。
- 注釈までの縦距離は、通常の語句の場合と空欄の場合とで別々に調整できる（CSS側で`.term-note`と`.term-note-anchor-blank .term-note`に分かれている）。

### `##語句##` — 行内改行禁止

```
##『{伊勢|いせ}物語』##
```

- 途中で行が折り返されたくない語句のまとまりを`white-space: nowrap`で囲む。
- 中にルビや空欄を含めてもよい（再帰的に解釈される）。

### `…`（box内アイテムのみ有効）

```
①『作品名』…ここから先が説明文。折り返しても①の後ろの位置に揃う。
```

- box内アイテムの`text`にだけ効く（`renderItemBlock`の`hangingSplit`フラグがtrueの時のみ判定される）。
- 最初の`…`を境に、前半をラベル、後半を本文としてflexで横並びにする。

## 記法の優先順位・注意点

- 正規表現は`[[ ]]` → `{{ }}` → `{ | }` → `## ##`の順に試される。`{{`は`{`より先に判定しないと、二重中括弧が壊れたルビとして誤解釈されるため順序が重要。
- `splitTopLevel`は`{ }`と`[ ]`の深さを数えて、ネストの内側にある`|`を区切りとして扱わないようにしている。`{{語句|注釈}}`のように`|`が複数箇所ある場合、最後のトップレベル`|`が語句と注釈の境目になる。
- 全角カッコ（｢「『（　｣」』））は自動で字間調整用のspanに包まれる（`appendKernedText`）。記法とは無関係に、通常の文章中でも常に効く。
